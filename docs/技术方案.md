# PixelPress 图片压缩工具 — 技术方案

> 版本 1.0 · 2026-10-16 · 目标平台 Windows x64（onedir exe，免装 Python）

---

## 1. 项目目标与范围

一个本地离线、界面专业级的批量图片压缩工具。核心诉求三条：

1. **压缩能力**：主流格式全覆盖，无损/有损双模，质量与缩放可调；
2. **界面规格**：达到商业专业软件（Capture One / ImageOptim / Affinity 一类）的布局与做工水准；
3. **交付形态**：PyInstaller 打包为单目录 exe，用户端零依赖。

**明确不做**（避免范围蔓延）：动图多帧重编码（GIF/WebP 动画默认跳过并标注原因）、云上传、格式转换以外的编辑功能（裁剪/调色/水印）、命令行批量工具（仅保留 `--headless` 自检入口用于打包验收）。

---

## 2. 技术选型与实测依据

选型不是拍的，是在本机（Python 3.14.3 / Pillow 12.3.0 / PySide6 6.12.0）跑 `scripts/benchmark_codecs.py` 实测出来的。

### 2.1 关键实测结论

| 实测项 | 结果 | 结论 |
|---|---|---|
| Pillow 原生编解码覆盖 | JPEG / PNG / WebP / AVIF / TIFF / BMP / GIF / ICO / TGA / PPM 全部可用，AVIF 无需第三方插件 | 引擎底座用 Pillow 12 |
| WebP 无损 vs PNG 无损（UI 截图） | 502 B vs 5,849 B（**小 91%**，且逐位无损） | 无损模式下 WebP 是压倒性选择，UI 需主动暴露该事实 |
| Pillow PNG 无损对照片 | 2,515 KB → 2,374 KB，仅省 5.6% | 单靠 zlib-9 不够 |
| oxipng 重压缩 PNG | 照片 2,515 KB → 2,235 KB（**−11.2%**）；图形 5,849 B → 1,433 B（**−75.5%**） | 内置 oxipng，收益显著 |
| oxipng `--zopfli` | 2,234,844 B → 2,233,624 B（再省 0.05%），耗时 1.28 s → 11.7 s（**10 倍**） | 不启用，性价比不成立 |
| pngquant | 照片用例直接失败（rc=99）；图形 5,352 B 输给 Pillow mediancut 的 1,983 B；且为 GPL-3 | **排除** |
| Pillow `quality="keep"` | 390 KB → 339 KB（−13%），PSNR 79.74 dB（**非** inf） | 是"保持量化表重编码"，不是逐位无损；命名必须诚实 |
| AVIF 无损 | Pillow 未暴露 lossless 参数，q=100 仅 48.28 dB | AVIF 只提供有损模式，UI 中禁用其无损选项 |
| JPEG 质量曲线 | q92→339 KB/41.4 dB；q85 4:2:0→158 KB/40.3 dB；q75→85 KB/39.6 dB | 质量预设按此标定 |
| 本机字体 | Outfit、JetBrains Mono **均未安装** | 字体必须随包内置，否则设计退化到 Segoe UI |
| Archivo 变量字体在 Qt 6.12 | 注册出 9 个命名实例；400/500/600/700 渲染墨量 1212→1685 递增 | 单个 643 KB 变量字体即可覆盖全字重，无需 4 个静态文件 |
| 中文字形回退 | 单字体族渲染墨量 211，显式回退链 249（+18%） | 必须用 `QFont.setFamilies()` 给出回退链，否则中文回退到劣质字形 |
| 离屏平台插件 | offscreen 无系统字体库，中文全部渲染为方框 | 像素审计可用 offscreen，**截图裁决必须在实机插件下渲染** |

## 4. 压缩能力矩阵

| 目标格式 | 无损模式 | 有损模式 | 引擎 |
|---|---|---|---|
| **PNG** | oxipng `--opt 2/4/6 --strip safe`（回退 Pillow zlib-9） | 调色板量化 256/192/128/96/64/48/32/16 色（mediancut） | oxipng / Pillow |
| **WebP** | `lossless=True, method 4/6` | `quality 1–100, method` | Pillow |
| **JPEG** | 「视觉无损」`quality="keep"`（源为 JPEG）+ optimize + progressive；源非 JPEG 时该组合禁用 | `quality 1–100`，quality≥90 自动 4:4:4，否则 4:2:0，progressive | Pillow |
| **AVIF** | **不可用**（UI 禁用并说明原因） | `quality 1–100, speed 8/6/4` | Pillow |
| **TIFF** | deflate / LZW | 不可用 | Pillow |
| **GIF** | 不可用 | 调色板 256 色（可能达成逐位无损，取决于源） | Pillow |
| **BMP** | 无压缩 | 不可用 | Pillow |

「保持原格式」为默认策略；用户可显式选择目标格式。**格式转换时的硬约束**：目标不支持透明而源含透明通道 → 按用户选定背景色（默认 `#FFFFFF`）合成，并在该文件行显式标注「已铺底」；不静默丢 alpha。

## 5. 核心流水线（单文件）

```
读取字节 → 探测格式/动画 → 解码
   → EXIF 方向烘焙（exif_transpose，避免剥离元数据后图像旋转错乱）
   → 模式规整（P→RGBA / CMYK 保留给 JPEG / 16bit 保留给 PNG·TIFF）
   → 缩放（LANCZOS，仅百分比、锁纵横比）
   → 元数据策略套用（full / slim / strip）
   → 编码（按矩阵择优）
   → 校验（重新解码确认尺寸，读实际体积）
   → 无收益保护（输出 ≥ 原始则原样落盘并标注）
   → 写盘（原子替换：写临时文件再 os.replace）
```

### 5.1 元数据策略（默认 slim）

| 策略 | ICC | EXIF 方向 | GPS/相机信息 | 其它 |
|---|---|---|---|---|
| `full` 保留全部 | 保留 | 烘焙后归一 | 保留 | 其余 EXIF 标签保留；XMP 不传递（Pillow 需显式传参，本版未做） |
| `slim` 精简（默认） | **保留**（防偏色） | 烘焙后归一 | **剥离** | EXIF 整体剥离 |
| `strip` 全部剥离 | 剥离 | 烘焙后归一 | 剥离 | 全部剥离 |

方向始终烘焙进像素，三种策略都不会产生旋转错乱。

**实现要点（踩过的坑）**：Pillow 的编码器在没收到显式 `icc_profile` / `exif` 关键字时会回退读取 `im.info`，所以"什么都不传"并不等于"剥离"——必须主动从图像对象上移除这些键。另外 `Image.getexif()` 返回的是活的 Exif 对象，删除其 Orientation 标签会连带影响随后的方向烘焙，因此元数据提取必须基于原始字节构造新对象，不能原地改。

### 5.2 安全与稳健

- 解压炸弹：设像素上限 **5 亿像素**，超限直接拒绝并给出明确原因（不静默崩）。
- 单文件异常隔离：任一文件失败只标记该行，批量不中断。
- 输出原子写：先写 `.part` 再 `os.replace`，中途失败不留半截文件。
- 原地覆盖模式默认关闭；开启后需二次确认，且强制保持原格式（否则会留下改名后的文件和过期原文件）。
- **无收益保护只对同容器生效**：压缩结果更大且输出容器与源一致时，原样写入源文件字节并标注「已优化」；若用户显式做了格式转换，则照常转换并汇报体积变化——把 PNG 字节写进 `.jpg` 路径是对用户的欺骗。

### 5.3 预览加载

预览图统一走 **Pillow** 解码后再转 QPixmap，而不是 `QPixmap.load()`：Qt 的图片插件不覆盖 AVIF / HEIC，用 Qt 加载会让这两种主推格式的预览静默空白。

## 6. 参数与编码器映射

**质量（1–100，仅在有损模式生效）**：直接映射到各格式原生 quality。因各格式标尺不同（WebP q80 已相当激进，AVIF q80 仍偏高质量），UI 在质量滑杆下方给出**当前格式的实时预估**（"预计 −62% · 画质优良"），预设档位为 低/中/高/极高。

**努力度（快速/均衡/极致）**：给编码器"效率 vs 时间"的选择权。

| 努力度 | oxipng | Pillow PNG | WebP method | AVIF speed |
|---|---|---|---|---|
| 快速 | `--opt 2` | compress_level 6 | 4 | 8 |
| 均衡（默认） | `--opt 4` | compress_level 9 | 6 | 6 |
| 极致 | `--opt 6` | compress_level 9 | 6 | 4 |

**缩放**：百分比 5–100%（默认 100），锁纵横比，快捷档 100 / 75 / 50 / 25，实时显示换算后的目标像素尺寸。

### 7.4 识别性细节（"值得记住"的部分）

1. **节省量条形图**：每个文件行用一条水平条表达压缩比，朱红填充＝已省比例，长度即数据。这不是装饰，是把抽象的百分比变成可扫读的视觉量。
2. **顶栏半调网点纹理**：程序化绘制（QPainter）的网点渐变，随主题换色，是所有装饰中唯一"有出处"的——它本身就是印刷技法。
3. **数值全等宽 + 右对齐 + 千分位**：`1,048,576` 与 `4,221` 的位数不跳动，扫读时不会眼花。
4. **微大写小标签 + 真实字距**：`压缩设置` 上方的小标签（如 `ENGINE`）用代码设字距，做出编辑部的克制品味。

### 7.6 排版与布局的实测修正

五处只有量出来才会发现的问题，已修正并写进回归断言：

1. **QSS 的 `letter-spacing` / `text-transform` 在 Qt 里无效**。微大写小标签的字距必须用 `QFont.setLetterSpacing(AbsoluteSpacing, …)` 在代码里施加，否则字距设置被静默忽略（相邻项目的样式表里就留着这类无效规则）。
2. **两个整句复选框并排会把卡片顶宽**：`无收益时保留原文件` + `原地覆盖源文件` 一行需要约 270 px，把设置卡的最小宽度抬到 363 px，而滚动区视口只有 333 px，右边缘被永久裁切（横向滚动条是关闭的）。改为纵向堆叠后卡片最小宽度降到 318 px。同类问题也出现在不换行的长等宽标签上，均改为 `setWordWrap(True)`。
3. **QSpinBox 的 `NoButtons` + QSS 会把行编辑压成 1 px**：实测 74 px 宽的数值框，内部 `QLineEdit` 只有 1 px，数值被画在框外，用户只看到自绘的 +/- 图标。修复方式是保留原生符号（让 QStyleSheetStyle 算出正确的编辑区），QSS 只把按钮宽高设为 0，并在行编辑右侧留 24 px 文字边距。回归断言直接检查行编辑宽度与数值墨量，不再只检查“+/- 画出来了没有”。
4. **队列固定列会吃掉「节省」列**：名称列 `Stretch` 在窄窗口被压到最低，右侧固定列仍按 158 px 绘制百分比，文字超出单元格后被视口裁掉，且没有水平滚动条。现在名称列宽度由视口反算（下限 180 px），总和超宽时 `QTableView` 出现水平滚动条；节省百分比按字体实测宽度右对齐排布，不越过单元格。
5. **预览“适应窗口”在矮舞台上把图缩成缩略图**：预览区只有约 200 px 高时，1600 px 的图被整体缩到 14%，既看不清也没有滚动条。改为默认**适应宽度** + `QAbstractScrollArea` 双滚动条，100% 时双向滚动；上下分栏可拖动，把舞台放大。

### 7.7 交互清单
- 拖放：文件/文件夹拖入窗口任意位置；拖入时窗口边缘出现朱红虚线框 + 网点加亮。
- 快捷键：`Ctrl+O` 添加文件、`Ctrl+Shift+O` 添加文件夹、`Delete` 移除选中、`Ctrl+Enter` 开始、`Esc` 取消、`Ctrl+1/2` 切换无损/有损、`Ctrl+D` 切换主题、`Ctrl++/-/0` 预览缩放/复位。
- 队列每行：勾选框（参与/跳过）、悬停高亮、单击选中并在预览区加载；无结果时状态列显示「待处理」，运行/取消/完成后的状态徽标同步更新。
- 空状态：队列为空时卡片内显示网点图 + "拖入图片或文件夹" 引导文案。
- 空转保护：未添加文件时「开始压缩」禁用；压缩中设置控件禁用，改动在下一批前生效。
- Toast：非阻塞提示（添加 12 个文件 / 已复制路径 / 3 个文件被跳过）。
- 任务状态：`待开始 → 运行中 → 正在取消 → 已完成 / 已取消`，顶部徽标、按钮文案和进度条颜色同步切换；点击取消立即反馈并等待本轮已开始的文件完成。
- 完成态：任务卡片切换为结果摘要（总节省大号数字 + 网点条），可一键打开输出目录。

## 8. 批量与并发

- `QThreadPool`，默认 `min(4, CPU 核心数)` 线程；每线程独立处理一个文件，Pillow 在解码/编码段释放 GIL，真实并行。
- oxipng 走子进程（`subprocess.run`，超时 300 s），不占 GIL。
- 取消：只派发等于线程数的任务，其余留在 GUI 线程队列中；取消后不再派发新文件，已开始的文件完成后停止。这样不会出现“未派发任务静默返回、runner 永远等不到完成”的挂起，也已完成的文件结果保留。
- 进度：按文件计数确定进度（N/M）；行内状态胶囊显示「待处理 / 处理中 / 完成 / 已优化 / 跳过 / 失败」，汇总区实时更新累计节省字节。
- 结果行状态机：`待处理 → 处理中 → 完成 / 已优化（无收益）/ 跳过（原因）/ 失败（原因）`。

## 10. 打包方案与验收

**PyInstaller onedir**（`PixelPress.spec`），datas 登记：`app/assets/fonts/*.ttf`、`vendor/oxipng.exe`；hiddenimports 补 `pillow_heif`；excludes 显式排除本机已装但本项目不用的重依赖（`torch`、`onnxruntime`、`onnx`、`modelscope`、`numpy`、`pytest` 等），避免被间接收集。

### 10.1 实测产物体积（本机构建）

| 项目 | 数值 |
|---|---|
| 总计 | **120.3 MB / 176 个文件**（初版 161.3 MB，裁剪后降 25%） |
| `PixelPress.exe` | 3.06 MB（PyInstaller 6 的薄启动器） |
| 随包字体 | 4 个 ttf，1.0 MB |
| `vendor/oxipng.exe` | 968 KB |
| 主要占用 | PySide6 ≈ 96 MB、顶层 DLL ≈ 49 MB、PIL ≈ 13 MB |

**裁剪与保留（均为实测结论）**：

- 裁掉 `opengl32sw.dll`（20.6 MB，纯栅格界面不需要软件 OpenGL 回退）、`Qt6Quick/Qml/Pdf/Network/Svg` —— 裁剪后 `--headless` 与实机窗口均正常。
- **`libx265`（22.7 MB）必须保留**：它只是 HEVC *编码器*、本工具从不写 HEIC，但 pillow-heif 的 libheif 硬链接它，裁掉后 `--headless` 立刻报 `HEIC 不可用`。这是"以为裁掉安全、实测不安全"的典型，故把结论写进 spec 注释与验收脚本。
- `numpy` 确认未入包（Analysis TOC 里出现的只是 hook 搜索路径字符串，不等于收集了包）。

### 10.2 冻结环境的两个必踩点

1. **入口脚本必须在包外**：PyInstaller 以顶层模块执行入口脚本，包内文件用相对导入会直接 `ImportError: attempted relative import with no known parent package`。故入口是根目录的 `PixelPress.py`，用绝对导入 `from app.main import main`。
2. **资源定位要用 `sys._MEIPASS`**：PyInstaller 6 把一切放进 `_internal/`。用 `sys.executable.parent` 找资源会让随包的 `oxipng.exe` 和字体全部"隐身"（表现为界面能开、引擎降级）。`app_root()` 以 `_MEIPASS` 为准，并额外优先查找 exe 同级目录，使用户可以自行替换 `vendor/oxipng.exe` 而不必重新打包。
3. **`--headless` 绝不能抛异常**：windowed exe 遇到未捕获异常会弹模态框并保持进程存活，自动化验收会把"弹框等人点"误判成通过。自检路径整体 try/except 并返回非零码。
4. **重定向输出要是 UTF-8**：冻结 exe 写入文件时用控制台代码页（本机 CP936），中文报告会变乱码；对非 tty 输出显式 `reconfigure(encoding="utf-8")`。

**四步验收**（沿用已在本机验证过的流程）：

1. **入包证据**：`build/PixelPress/Analysis-00.toc` 与 `PYZ-00.toc` 中 grep `app.ui.queue_model`、`pillow_heif` 等模块点分名，确认被收集；**先取证再删 `build/`**。
2. **冻结环境可用**：`PixelPress.exe --headless` 的 `ExitCode == 0`，覆盖格式探测 → 解码 → 缩放 → 各编码器 → 校验全链路，不依赖 UI。
3. **实机窗口**：先回显确认 `QT_QPA_PLATFORM` 为空，再 `Start-Process -PassThru` → 等待 10 s → 进程存活（记录工作集与线程数）。仅证明已进入事件循环，不作为界面正常的证据。
4. **视觉裁决**：`scripts/ui_preview.py` 离屏渲染 + 像素审计全绿（尺寸下限、指示符真渲染、调色板泄漏哨兵、标签透明、卡片有文字、横向不裁切、导航选中态），产出 PNG 交你目视确认。

## 12. 已知边界

1. **JPEG 无比特级无损**：`quality="keep"` 是"保持量化表 + 优化霍夫曼 + 渐进式"，实测 79.7 dB（视觉不可辨），但非逐位相同。UI 文案严格写作「视觉无损」，不写「无损」。若日后需要比特级无损，接 `jpegtran` 即可（编码器注册表已预留位置）。
2. **AVIF 无无损模式**：Pillow 12 未暴露 libavif 的 lossless；UI 禁用该组合并给出原因。
3. **动图跳过**：GIF/WebP 动画按需求未纳入，队列中标注「动图暂不支持」并跳过，不静默处理首帧。
4. **HEIC 仅读不写**：pillow-heif 可解码 HEIC；输出 HEIC 需商业授权考量，故仅支持读取，输出侧自动落到可写格式。
5. **不内置 CJK 字体**：依赖 Windows 自带微软雅黑 UI；若在精简系统上缺失，回退到 Segoe UI（中文仍可显示，观感略降）。
